# Геонапоминалка

Android-приложение (Kotlin, MVVM + Repository) для напоминаний, привязанных к точке на карте.
Реализация соответствует ТЗ: создание задач долгим тапом по карте, foreground-сервис
геолокации, уведомления с кнопками «Выполнено»/«Отложить», менеджер задач, настройки.

## Как открыть и собрать

1. Откройте папку проекта в Android Studio (Koala/2024.1+ рекомендуется).
2. Скопируйте `local.properties.example` в `local.properties` (нужен только `sdk.dir`,
   Android Studio обычно проставляет это сама). API-ключ карты НЕ требуется.
3. Дайте Gradle синхронизироваться (скачает зависимости из google()/mavenCentral()).
4. Запустите конфигурацию `app` на устройстве/эмуляторе.

## Карта

Используется **OSMDroid** (данные OpenStreetMap) — бесплатно, без API-ключа и привязки карты.
- Обычная схема — тайлы **CARTO Basemaps** (light_all), а не штатный `TileSourceFactory.MAPNIK`:
  прямой `tile.openstreetmap.org` активно блокирует запросы из приложений (403 Forbidden) —
  их публичный сервер не предназначен для встраивания, только для эпизодического
  браузерного использования. CARTO — тоже бесплатно, без ключа, но без такой блокировки.
- "Voyager" — более цветной/подробный стиль того же CARTO.
- "Спутник" — публичные тайлы Esri World Imagery (тоже бесплатные, без ключа).
- "Гибрид" — тот же спутник Esri + полупрозрачный слой подписей CARTO поверх (дороги, названия) —
  собственного гибридного режима у бесплатных провайдеров нет, поэтому это композиция двух тайлов.
- Все источники — в `util/TileSources.kt`; стиль синхронизирован между кнопкой на карте
  и разделом «Стиль карты» в настройках через один и тот же ключ `mapType` в `SettingsRepository`.
- **Про номера домов**: у CARTO нет отдельного слоя с номерами домов ни в одном из стилей —
  это общее ограничение упрощённых бесплатных базовых карт. Пробовали зеркало классического
  OSM Standard на серверах Wikimedia (`maps.wikimedia.org`), но оно оказалось нестабильным
  (тайлы не грузятся), поэтому такой пункт убран из списка стилей. Если номера домов
  принципиально нужны — единственный практичный путь это платный тайл-провайдер с ключом
  (у Mapbox/MapTiler/Stadia Maps есть щедрый бесплатный тариф без требования карты, в
  отличие от Google).
- FusedLocationProviderClient (получение текущих координат) из Google Play Services
  остаётся — это отдельный бесплатный компонент, ключ карт для него не нужен;
  на устройствах без Play Services эту часть нужно будет заменить на LocationManager.
- Тайлы **кэшируются на диске** (`getExternalFilesDir("osmdroid_tiles")`, лимит 300МБ,
  без TTL — тайлы живут, пока не превышен лимит по размеру) — при повторном открытии
  уже просмотренной области тайлы берутся из кэша, а не скачиваются заново; сервер
  нагружается в основном при первом посещении новой области. `Configuration.getInstance()`
  у OSMDroid — синглтон на весь процесс, настраивается **только один раз** в
  `GeoApp.onCreate()`; экраны с картой (`MainActivity`, `MapPickerActivity`) НЕ должны
  повторно вызывать `.load()` — это было багом в одной из версий (повторный `load()`
  перечитывал настройки из `SharedPreferences` и откатывал путь кэша на дефолтный при
  каждом пересоздании экрана, из-за чего казалось, что тайлы не кешируются вовсе).
- Мелкая полупрозрачная подпись над полем поиска в левой части карты (`cacheSizeLabel`)
  показывает текущий размер дискового кэша тайлов — только для отладки/визуального
  контроля, обновляется раз в 5 сек (`util/TileCacheInfo.kt`). В консоль/лог не пишет —
  там важнее геоданные, размер кэша туда не попадает, чтобы не засорять лог. Можно
  убрать позже: сама функция `startCacheSizeMonitor()` в `MainActivity`, вызов из
  `onCreate`, и `cacheSizeLabel` из `activity_main.xml`.
- Поиск адреса — через **Nominatim** (`util/NominatimGeocoder.kt`), а не штатный Android
  `Geocoder`: у системного геокодера bounding box — лишь подсказка бэкенду (обычно Google),
  а не жёсткий фильтр, поэтому он может проигнорировать регион пользователя и вернуть
  одноимённую улицу в другой стране. Алгоритм: пробуем область вокруг пользователя
  нарастающего размера (~30 км → ~150 км → ~600 км) с `bounded=1` (у Nominatim это
  настоящий жёсткий фильтр); если нигде ничего нет — ищем без ограничения вовсе; из всех
  найденных кандидатов на каждом шаге берём реально ближайший по расстоянию, а не первый
  по релевантности из ответа API. Соблюдены лимиты политики использования Nominatim
  (не более ~1 запроса/сек, свой User-Agent) — это разовый поиск по нажатию пользователя,
  укладывается в рамки личного использования.
- Курсор «моё местоположение» и маркеры — кастомные векторные иконки для контраста
  на светлых стилях карты (штатные иконки osmdroid/Material слишком блёклые):
  курсор — `#E65100`, булавки задач — красные, булавка результата поиска — синяя.

## Что реализовано

- **data/** — Entity `Reminder`, Room DAO/Database, `ReminderRepository`,
  `SettingsRepository` (DataStore: тема, звук, вибрация, интервал, тип карты).
- **service/LocationForegroundService** — FusedLocationProviderClient, проверка расстояния
  до каждой активной задачи, антиспам-логика (cooldown 10 мин + гистерезис выхода из зоны).
- **receiver/NotificationActionReceiver** — обработка кнопок уведомления без открытия приложения.
- **ui/MainActivity** — карта на весь экран, бургер-меню, долгий тап → создание,
  тап по маркеру → удаление (с названием/описанием задачи в диалоге подтверждения),
  зум, поиск адреса (Nominatim, приоритет по местоположению пользователя),
  переключение типа карты.
- **ui/TaskEditActivity** + **MapPickerActivity** — создание/редактирование, координаты
  только для чтения, смена точки через отдельный экран карты. Диалог удаления
  тоже показывает название и описание задачи.
- **ui/TaskListActivity** — список активных/выполненных задач; диалог удаления —
  аналогично, с названием и описанием.
- **ui/SettingsActivity** — тема, интервал опроса, звук (RingtoneManager), вибрация, сброс данных.
- **GeoApp** — наблюдает `Flow<Int>` количества активных задач и запускает/останавливает
  foreground-сервис при переходе 0↔1 (п.1.6 ТЗ).
- **Боковое меню → «Закрыть совсем»** — принудительно останавливает сервис геолокации
  и завершает процесс приложения (`killProcess`), независимо от количества активных
  задач. В отличие от обычного «Выход» (просто закрывает экраны, сервис продолжит
  работать в фоне, если есть активные задачи — это штатное поведение), эта кнопка
  гарантированно ничего не оставляет висеть в фоне. Предупреждает, если есть активные
  задачи — уведомления по ним не придут, пока приложение не откроют снова.
- **Боковое меню → «Консоль»** (`util/AppLogger.kt`, `ui/LogActivity.kt`) — визуальный
  журнал работы сервиса геолокации в реальном времени: интервал опроса, полученные
  координаты, вход/выход из геозон, отправленные уведомления. Хранится в памяти
  процесса (до 500 последних записей), обновляется живьём через `StateFlow`. Кнопки
  и прочие UI-действия туда намеренно не попадают — только геоданные.
- Карта при запуске приложения центрируется на последней известной геопозиции
  пользователя (если разрешение выдано), а не на дефолтных координатах — координаты
  из `setupMap()` используются только как запасной вариант, пока геопозиция не получена.
- **Адаптивный алгоритм опроса местоположения** (`util/AdaptiveIntervalCalculator.kt`,
  `util/MotionState.kt`, `service/ActivityTransitionReceiver.kt`) — интервал опроса GPS
  подстраивается под расстояние до ближайшей активной задачи и скорость движения:
  `rawInterval = d / (v * K)`, clamp в [15с, 900с], далее поправки (IN_VEHICLE — всегда
  ÷2, побеждает над правилом медленной скорости; v < 0.5 м/с — ×1.5) и прогноз времени
  до входа в зону (сокращает интервал вдвое, если рискуем не успеть). Скорость — из
  Activity Recognition (типовая скорость по режиму: STILL/WALKING/RUNNING/ON_BICYCLE/
  IN_VEHICLE), либо из `location.speed`, если Activity Recognition недоступно. При
  переходе из состояния "стоит" в любое движение — мгновенный внеочередной опрос,
  не дожидаясь текущего интервала. Переключатель «Адаптивный режим» в настройках
  (по умолчанию включён) — главнее ручного списка интервалов, который при этом
  остаётся видимым, но задизейблен. Разрешение `ACTIVITY_RECOGNITION` запрашивается
  вместе с остальными при первом запуске; если пользователь включает адаптивный режим
  без него — показывается объяснение и разрешение запрашивается повторно, но режим
  всё равно включается (просто менее точно, по GPS-скорости).
- **Живое применение ручного интервала**: раньше сервис читал интервал только один раз
  при своём запуске — если поменять настройку, пока есть активные задачи, изменение
  применялось лишь при следующем перезапуске сервиса. Теперь сервис подписан на
  настройки через `Flow` и применяет новое значение сразу, без перезапуска, — это
  касается всех активных задач разом (опрос местоположения общий, не по одной задаче).
  Каждое изменение интервала (ручное и адаптивное) пишется в консоль/лог.

## Известные упрощения (можно доработать)

- Иконки — простые векторные заглушки, стоит заменить на дизайн-иконки.
- "Спутник" на Esri — публичный эндпоинт без гарантированного SLA; для продакшена
  лучше взять платный тайл-провайдер (Mapbox/MapTiler) или официальный Esri-ключ.
- Nominatim — тоже публичный бесплатный сервис с политикой добросовестного использования
  (~1 запрос/сек); для продакшена с большим числом пользователей потребуется свой
  инстанс Nominatim или платный геокодер.
- Адаптивный алгоритм оценивает скорость по типовым значениям для режима активности
  (например, IN_VEHICLE ≈ 15 м/с) или по `location.speed` из GPS, а не по накоплению
  дельт координат между обновлениями, как альтернативно допускало ТЗ — этого достаточно
  для устойчивой работы формулы и проще в реализации.
- На очень высокой скорости при небольшом радиусе зоны теоретически можно проскочить
  геозону между опросами даже с адаптивным алгоритмом (жёсткий пол `MIN_INTERVAL=15с`
  не позволяет опрашивать чаще) — осознанное решение в пользу экономии батареи, а не
  100% гарантии срабатывания на любой скорости.
